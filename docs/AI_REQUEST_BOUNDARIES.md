# AI 请求与模型路由边界

## 本地模型

公网供应商默认要求 HTTPS，并拒绝私有、回环、链路本地、保留或 IPv6 转换目标。
保存供应商时与真正发送时都会校验 DNS 的全部 A/AAAA 结果。发送使用校验后的 IP，保留原主机的 Host 和 TLS 证书校验，不进行第二次域名解析。
AI 携带密钥的 GET/POST 不跟随 302/307/308 等重定向。遇到跳转时请把供应商改为最终 HTTPS 接口。

Ollama 的本地地址需要部署管理员在环境文件中明确允许，例如：

```dotenv
OLLAMA_ALLOWED_BASE_URLS=http://localhost:11434,http://127.0.0.1:11434
```

修改后重启后端。名单按完整基础地址匹配，端口和路径均参与匹配；不接受通配符或网段。
只有 Ollama 使用此例外，不能借此给自定义公网 Provider 放开 HTTP 或私网。
私网例外仅覆盖回环、RFC1918 地址和 IPv6 ULA；共享地址、文档与保留地址不在例外内。
链路本地/云元数据（包括 `100.100.100.200`）及 IPv6 转换目标即使出现在名单中也会拒绝。
这只是指定本地模型的网络例外，不是全局私网开关。不要配置不受信任的本地服务。

## 主模型与降级

- `enabled=false` 的模型或供应商不进入主模型和备用模型路由。
- `is_default` 仅设置未配置路由时的默认主模型，不授予备用权限。
- `is_fallback=true` 才授权模型接收失败降级请求，优先级按 `priority` 从小到大排列。
- 主模型的 `allow_cross_provider_fallback` 默认关闭。需要跨供应商时管理员应明确开启，且目标仍必须启用并标记为备用。
- 账号 `features.ai_allow_cross_provider_fallback=false` 可进一步关闭该账号的跨供应商降级。
- 主动指定模型、群路由、账号路由中已配置但停用/无权限的模型返回不可用，不悄悄改用全局模型。

账号可通过现有 `features` 配置进一步收窄模型范围：

```json
{
  "ai_allowed_model_ids": [1, 2],
  "ai_group_model_ids": {"9001": [1]},
  "ai_allow_cross_provider_fallback": false
}
```

这些限制同时作用于主模型与备用模型。群键使用内部路由 ID；群范围与账号范围取交集，不能扩大账号授权。
不存在范围配置时沿用管理员共享模型池；显式空列表或无效列表拒绝全部模型。
群 `ai_model_id` 和账号 `ai_model_id` 选择主模型，不单独授权其它备用模型。

## 期限与取消

`AI_CALL_DEADLINE_SECONDS`（默认 120 秒）覆盖整条调用链，包括发送前解析、重试与备用请求；每个模型自身的超时仍然有效。
调用超时会取消正在等待的 HTTP 调用，外部取消会继续向上传播，不触发后续备用请求。
机器人入口另外执行有界排队与账号停止取消；限额配置见 `.env.example`。

## 会话迁移与回退

`0017_ai_scope_key` 为 `(account_id, scope_key)` 增加非空唯一约束，以避免 SQLite/PostgreSQL 的 nullable 组合唯一键允许重复会话。
相同账号、scope、group_number、user_id 的历史重复会话合并到最早记录，消息全部迁入该记录并重算数量。
并发新建以数据库唯一约束仲裁，冲突方重读获胜记录。

升级前备份数据库。旧进程不知道新增的非空 `scope_key`，不要让旧版和新版同时写同一数据库。
需要回退旧版程序时应停止服务并恢复升级前快照；已接受的新写入不会自动回灌旧快照。
迁移的 downgrade 可删除新增约束和字段，但不会拆回已合并会话，不能代替完整快照恢复。
