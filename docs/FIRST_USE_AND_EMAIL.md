# 首次使用与失败邮件

登录后台后，从首次提示点击「开始分步设置」。以后可以在左侧「新手指引与文档」重新打开，按「上一步 / 下一步」阅读；操作文档支持关键词搜索。教学进度按后台用户保存，配置状态由真实账号、仓库、群权限与投递记录决定，不会因点击下一步而伪造成功。

推荐顺序：连接 QQ 机器人 → 连接 GitHub Token → 绑定群并允许主动发送 → 测试群通知 → 配置失败邮件。没有设置权限的用户会看到需要管理员协助的提示。

## 对照 QQ 设置图片

后台第 3 步「绑定群，再打开主动推送」以及「绑定成功，为什么更新不推送？」文档内置三张实图，点击可放大并切换原图，键盘 Enter 打开、Esc 关闭。

1. [群机器人设置页](../frontend/src/assets/help/qq-group-bot-settings.jpg)：确认「机器人主动在群聊内发言」已开启，找到下方「机器人权限设置」。
2. [主动消息权限页](../frontend/src/assets/help/qq-proactive-message-permission.jpg)：打开「允许主动发送消息」。
3. [接收群消息范围](../frontend/src/assets/help/qq-group-message-scope.jpg)：按需选择接收内容。该项与主动发送权限分开设置，图中的选择是示例，绑定时仍需 @ 机器人。

图中管理员等其他选项按所需功能授权；QQ 版本不同，位置或文案可能略有差异。完成后回后台点击「检查群权限」和「测试主动通知」。图片使用本地打包资源，不依赖上传者电脑中的 QQ 图片路径。

## 在后台配置发信

打开左侧「邮件告警」。发信账号与收件邮箱分别设置，项目不预置任何个人收件地址。

1. 选择「腾讯 Agent Mail」或「SMTP 邮箱」。
2. Agent Mail：点击「连接发信邮箱」，在本页打开腾讯授权链接，由邮箱本人完成 OAuth。点击「检查发信授权」查看实际发件地址。更换发件人需要重新授权。授权失败不会自动反复启动 OAuth。
3. SMTP：填写服务商提供的 SMTP 主机、端口、SSL/TLS 或 STARTTLS、发件地址、登录账号与授权码。仅支持加密连接。授权码由后台加密保存，页面不回显；编辑时留空保留原值，明确勾选清除才会删除。通常授权码与网页登录密码不同。
4. 填写收件邮箱，勾选需要提醒的异常类型，启用告警并保存。默认提供自动化任务失败、群通知失败、GitHub 异常和机器人连接异常；可增加系统错误。
5. 点击「保存并发送测试」，在收件箱或垃圾箱确认，并查看下方最近发信记录。

邮件正文只包含失败时间、分类和经过脱敏的错误，不附加服务环境文件或邮箱凭据。发信设置仅允许具有 `system:manage` 权限的后台用户管理。

## Agent Mail 工具与服务器

根据[腾讯官方接入文档](https://agent.qq.com/doc/cli-setup.md)，非 Docker 主机可以安装官方 CLI：

```bash
npm install -g @tencent-qqmail/agently-cli
```

本项目 Docker 镜像构建时固定安装官方 CLI 1.0.18，保留其 Apache-2.0 许可。后端直接调用原生可执行文件，不通过 shell 拼接命令。需要自定义工具路径时在服务器环境配置 `AGENTLY_CLI_PATH`，修改后重启后台。`DATA_DIR/agent-mail` 用于本应用的 CLI 配置目录；在 Compose 中 DATA_DIR 位于持久化 `/data` 数据卷。外部邮箱服务的额度与授权要求仍由腾讯决定。

本机授权不会自动带到另一台服务器；服务器首次部署请重新授权，并确认 CLI 在该主机能使用其凭据存储。Linux 容器内的邮箱 OAuth / 凭据持久化尚需实际服务器验收；如果环境不支持，可在同一后台配置 SMTP。不要把邮箱 OAuth 凭据或本机数据卷放进上传源码包。

## 发送结果与重试

- 失败日志按选择的分类进入数据库邮件队列。相同错误约 3 分钟内合并提醒；故障发送最多尝试 3 次。后台调度器每 30 秒处理队列，不要求浏览器持续打开。
- Agent Mail 返回入队确认或 SMTP 接受收件地址后，显示「服务已接收」。这不证明最终进入收件箱；实际到达还取决于收件服务、退信与垃圾邮件策略。
- 重启保留队列与尝试次数；发送中崩溃的记录在 5 分钟后恢复。若最后一次尝试被中断，记录显示「结果未确认」，不超出预算自动重发，应核对收件箱。外部服务接受后、确认落库前若进程中断，仍可能重复发送，不能保证跨服务的恰好一次投递。
- 关闭邮件告警会取消尚未发送的队列；更改收件地址或通道后旧队列不会改投到新地址，已在发信中的请求无法撤回。
- 发信异常只记录到邮件队列，不再生成同类邮件告警，防止递归。Webhook 告警仍保留，与邮件设置独立。

## 仓库清单同步

后台约每分钟检查完整授权仓库清单。GitHub 删除、转移或收回 Token 访问权限后，相关自动接入仓库退出当前列表与计数，历史保留；列表请求失败时保留原状态。仪表盘和仓库表可见时每 10 秒刷新，重新切回页面时也会刷新。配置中的动态轮询间隔仍独立生效；刷新清单不会不断重置已有动态轮询的计时。

已有库升级前备份。新增迁移 `0010_guides_email_sync` 不删除仓库或投递历史。新数据库部署完成后，从后台教学入口重新连接外部账号。
