## 📢 版本概述

本次更新加固仓库与 AI 数据边界，修复机器人命令、任务恢复、备份和旧版更新提醒，并完善现有管理台的消息发送、模型编辑和任务操作。包含数据库迁移，升级前请备份数据、环境配置及自定义插件；不要让新旧版本同时写入数据库。

## ✨ 新增功能

- **模型编辑与备用授权**：可保留模型 ID 编辑优先级、超时、重试、Token 上限和启停状态；跨供应商降级需明确开启，备用模型也必须启用并授权。
- **可恢复运行记录**：新增持久 QQ inbox、任务成功回执及调度 owner 租约，减少重投和重启造成的重复处理；不确定的外部发送保留人工核对状态。
- **任务预览与恢复演练**：定时任务支持按类型填写参数、时区触发预览和试运行；Docker 恢复脚本可先在隔离数据库演练。

## 🔧 改进与优化

- **消息工作台**：历史筛选与发送目录分别按账号加载，保护账号切换的乱序响应；支持已登记联系人、群别名和内部映射 ID 的分页搜索、加载更多及增量消息。
- **运行恢复**：AI 等待队列有容量与期限，停止账号取消旧请求；Redis 领取、续租和回收使用原子条件操作，Worker 监督消费协程并提供消费健康检查。
- **插件与更新**：自定义插件代码使用持久目录，加载前校验 manifest；版本检查合并并发请求，支持 ETag、限流退避和最后成功结果的过期标记。

## 🐛 问题修复

- 修复 QQ 仓库命令查询与执行超出本账号、本群授权范围，以及删除用户后私有仓库变为全局共享的问题。
- 修复 AI 开启时插件命令被吞、备用模型未授权仍被调用、会话 nullable 组合键允许并发重复等问题。
- 修复持续推送时 WebSocket 会话撤销检查延迟、OAuth state 可重复使用及无效 Webhook 签名造成日志写放大的问题。
- 修复备份管道掩盖导出失败、未完成备份参与保留清理，以及“稍后提醒”永久隐藏当前版本的问题。提醒默认六小时后恢复。

## 🔒 安全与兼容性

- AI 请求发送时重新校验网络目标并固定到已验证 IP，拒绝携带凭据的重定向；本地 Ollama 需管理员显式设置 `OLLAMA_ALLOWED_BASE_URLS`，不全局放开私网。
- OAuth 使用持久一次性 state、发起会话、浏览器 nonce 和 S256 PKCE；FastAPI / Starlette 升级至通过本次依赖审计的版本。
- 保留旧 `/api/system/update` 结构、Release 源及五项资产命名；新增字段向后兼容。v1.4.12 的失效 Token 需按兼容指南清理或桥接，不能由尚未安装的新版本自动修复。
- 插件仍是受信 Python 代码，权限声明不是安全沙箱；历史全局仓库需管理员复核原归属。
- GitHub 检查和推送重试任务按创建者的当前权限执行；没有有效创建者的旧敏感任务需管理员重新创建授权，默认备份和清理任务不受影响。

## 🔄 升级与数据迁移

- **兼容性**：执行 `0016_repository_oauth_scope`、`0017_ai_scope_key`、`0018_runtime_recovery`；旧版和新版不可混写新 schema。
- **配置和数据**：保留账号、原密钥、通知规则、插件绑定及会话消息；重复会话合并。自定义插件默认位于 `DATA_DIR/plugins`，升级前另行备份整个目录。
- **回退方式**：维护闸门开放前的原生升级失败可回退代码和升级前快照；新版本已接受写入后必须先停写并保存当前数据，再恢复旧快照，不能直接切旧代码。详见[迁移与回退说明](https://github.com/yuchen0x1/AI-QQ-Bot/blob/main/docs/MIGRATION_1.6.0.md)。

## ⚠️ 已知问题

- GitHub API 不可达或触发出口限流时，旧进程可能暂时无法发现新版本；v1.4.12 配置失效 Token 时需先按兼容指南修复。不能承诺所有未升级旧进程都会立即收到提醒。
- QQ 上游不提供本项目可控制的端到端 exactly-once；发送中断后需核对不确定记录。多副本部署仍需验证连接 owner 与发送任务放置，不能只增加副本即作为集群生产验收。
