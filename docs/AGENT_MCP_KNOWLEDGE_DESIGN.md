# Agent / MCP / 知识库能力设计（评审稿）

状态：设计评审稿，未实现。本文是 v1.3.x 之后引入 Agent、MCP 与知识库的前置设计，覆盖工具权限、任务隔离、数据保留与审计四个必须先回答的问题。在此之前不发布任何相关功能。

## 1. 目标与边界

- 平台定位不变：QQ 官方机器人的多账号管理台。Agent/MCP/知识库是给已有账号、群绑定、通知与插件体系增加的可选能力，不改变 QQ 官方协议的能力边界。
- 安全边界不变：插件与工具都是受信代码 / 受信服务器，平台不宣称沙箱；所有对外行为必须可审计、可撤销、可限额。
- 失败默认安全：任何工具调用在权限不明确、配额耗尽、审批缺失、上游不可用时一律拒绝并记录，而不是降级猜测。

## 2. 工具权限模型

### 2.1 命名空间与声明

- 现有插件权限集（`message:reply`、`storage:config`、`ai:request`、`http:request`）保持不动；新增工具命名空间 `tool:<分类>:<动作>`，例如 `tool:search:web`、`tool:docs:read`、`tool:mcp:call`。
- 工具提供方（插件、MCP 服务器、内置工具）在 manifest 中声明所需权限；运行时未声明的权限拒绝调用，与现有 `ALLOWED_PERMISSIONS` 语义一致。
- `tool:mcp:call` 细化为按服务器与工具名授权：`mcp:<server>/<tool>`，避免"授权了一个 MCP 服务器等于授权了它未来所有工具"。

### 2.2 授权流程

1. 管理员在后台「AI 中心 → 工具权限」为每个插件/Agent 配置权限位，默认全空。
2. 高风险权限（外部 HTTP、MCP 调用、知识库写入）必须显式开启，并支持设置每日调用配额与单次超时。
3. 权限变更写入现有 `audit()` 审计（actor、动作、前后值），复用 RBAC 的 `plugin:view` / `plugin:manage` 同级权限点（新增 `tools:view` / `tools:manage`）。
4. 插件侧的每次 `has_permission` 判定已进入权限审计环形缓冲（v1.3.x 引入）；工具调用复用该机制并持久化到数据库表 `tool_call_logs`。

### 2.3 配额与限额

- 配额按「插件 × 工具 × 天」计数，超出后拒绝并告警；计数持久化，重启不丢失。
- 单次调用超时默认 30 秒，可按工具覆盖；超时视为失败并计入错误率。

## 3. 任务隔离

### 3.1 执行模型

- 工具调用不与机器人连接共享事件循环内的阻塞工作：CPU 密集或阻塞 IO 的工具放入 `asyncio.to_thread` 或独立进程池，避免拖慢消息事件流与 WebSocket 推送。
- Agent 多步任务（规划 → 工具调用 → 汇总）在一个受控任务对象中执行：
  - 硬性步数上限（默认 8 步）与总时长上限（默认 120 秒），超限终止并记录已发生的副作用。
  - 任务可被管理员取消；取消必须传播到正在执行的工具（进程级终止，而不仅是取消协程）。

### 3.2 隔离边界

- 工具进程不持有机器人凭据、数据库连接串或 `SECRET_KEY`；需要的上下文由平台按最小化原则注入（例如只传入搜索关键词，不传会话历史原文）。
- MCP 服务器作为独立子进程运行，工作目录专用、无网络外联白名单之外禁止；其 stdout 按协议解析，stderr 只进日志。
- 任何工具不得直接访问 SQLite/PostgreSQL 数据库文件；数据访问只能通过平台提供的显式工具接口。

## 4. 数据保留

| 数据 | 保留策略 |
|---|---|
| `tool_call_logs`（工具调用审计：谁、何时、什么工具、参数摘要、结果状态、耗时） | 默认 90 天，后台可配 7–365 天；超期由既有数据清理任务删除 |
| 工具返回的原始内容（网页、文档片段） | 默认不落库，仅在任务上下文中短存（任务结束即弃）；知识库入库内容除外 |
| 知识库文档与向量 | 保留到来源失效或管理员删除；删除时同步删除向量与索引条目 |
| Agent 任务上下文（多步中间状态） | 任务结束后保留结构化摘要 30 天，原始上下文即时清除 |

- 写入知识库的内容必须记录来源（URL / 上传者 / 采集时间）；无法溯源的内容不接受。
- 群消息原文进入知识库前需要管理员开启「消息采集」开关，且支持按群排除；默认关闭。

## 5. 审计

- 三类审计合流到统一查询界面（复用现有系统日志页的过滤体验）：
  1. 管理员操作审计（现有 `audit()`）。
  2. 插件/工具权限判定审计（环形缓冲 + `tool_call_logs`）。
  3. Agent 任务审计（任务创建、每步工具调用、终止原因、最终答复摘要）。
- 审计记录包含：时间、主体（插件/Agent/用户）、工具或权限、目标（URL/文档/群）、结果（allow/deny/error）、耗时；不记录消息原文与密钥。
- 错误率与配额面板复用 v1.3.x 插件指标的展示模式（错误率、平均耗时、最近错误）。

## 6. 知识库

- 存储：SQLite/PostgreSQL 表存文档与分块，向量检索使用平台已配置的 AI Provider 的 embedding 接口；不引入独立向量数据库服务，规模上限按单管理员自托管场景设计（万级分块）。
- 检索：按账号/群绑定的知识库范围过滤，未绑定任何知识库的会话不触发检索；检索命中数、来源文档始终随引用返回。
- 生成：AI 回复中引用知识库内容时必须带来源标识；检索失败或为空时按普通会话继续，不虚构来源。
- 写入通道：仅两种——管理员上传文件、带 `tool:docs:write` 授权的工具采集；群消息自动采集默认关闭（见第 4 节）。

## 7. MCP 客户端

- 仅支持 stdio 传输的本地 MCP 服务器（自托管场景不引入公网 MCP 网关）；远程传输在后续版本评估。
- 服务器注册需要管理员提供启动命令与工作目录，后台展示其工具清单与所需权限，逐工具授权后才可被调用。
- 供应链约束：MCP 服务器进程以独立低权限系统用户运行（与 qbot-updater 构建用户同级隔离）；其代码更新不在网页端进行，由服务器管理员手动维护。
- 已知风险与缓解：工具描述注入（提示注入的载体）——工具描述展示给模型前经过转义与长度限制；结果注入——工具结果进入上下文前标记为数据而非指令。

## 8. 威胁模型要点

1. 提示注入 → 工具参数混淆：所有工具参数由平台构造并做类型校验，模型输出只作为参数来源之一，高危参数（URL、路径）走白名单校验，复用告警 Webhook 的 SSRF 防护组件。
2. 权限漂移：插件更新后权限清单变化需管理员重新确认；版本对比展示权限 diff。
3. 资源耗尽：配额、步数、超时三重上限；Agent 任务并发默认 1。
4. 数据外发：`http:request` 与 MCP 调用记录目标域名；私网/回环目标默认拒绝（复用 `ALERT_ALLOW_PRIVATE_NETWORKS` 的语义与开关模式）。

## 9. 分阶段落地

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | 本设计评审定稿；权限点与数据表设计（`tool_call_logs`、知识库表） | 评审记录 |
| P1 | 工具权限模型 + 配额 + 审计落库；插件指标页扩展工具维度 | 权限拒绝/放行有审计，配额超限拒绝 |
| P2 | 任务隔离执行器（步数/超时/取消）+ 内置工具 2–3 个（搜索、文档读取） | 取消传播、超时终止有测试 |
| P3 | 知识库：上传、分块、embedding、按群检索与引用 | 检索有来源、未授权群不可见 |
| P4 | MCP 客户端（stdio）+ 逐工具授权 | 服务器崩溃不影响主进程，工具未授权即拒绝 |

每阶段独立发版；任何阶段未通过验收不进入下一阶段。
