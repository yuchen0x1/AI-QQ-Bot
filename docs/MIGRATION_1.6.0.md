# v1.6.0 数据迁移与回退

本版本沿用 SQLite / PostgreSQL、原有 `SECRET_KEY`、QQ OpenID 映射和 API 更新源。升级前必须保存完整数据库、环境配置和自定义插件目录。不要同时运行旧版与新版写入同一个数据库。

## 迁移内容

- `0016_repository_oauth_scope`：增加仓库归档和持久 OAuth state。非空但已不存在的所有者仓库归档、清理凭据并停用通知；历史空归属全局仓库保留，不能自动推断它们此前是否属于已删除用户。
- `0017_ai_scope_key`：增加模型跨供应商备用开关，默认关闭；为会话建立非空规范 scope key 和数据库唯一约束。重复历史会话合并到最早记录，保留所有消息及引用，不保持重复会话 ID 作为独立对象。
- `0018_runtime_recovery`：增加 QQ inbox、scheduler owner 租约和队列持久成功回执。首次启动自动执行 Alembic；迁移失败必须停止升级并保留错误，不能用 `stamp head` 跳过。

## 升级顺序

1. 原生部署使用独立 updater 的维护闸门和一致性备份；Docker 部署先运行 `bash backup.sh`，将 `.sql.gz` 及对应 `.sha256` 复制到受控的独立存储。
2. 停止全部旧 backend、worker、独立 scheduler 与外部写入者，避免新旧实例混写。保持原 `SECRET_KEY`，否则既有加密配置不可解密。
3. 安装经过 SHA-256 与来源验证的新版本，执行 `alembic upgrade head` 并启动。核对就绪探针、账号、仓库归属、通知规则、插件绑定及会话历史。
4. 内置插件仍由版本提供；自定义插件默认位于 `DATA_DIR/plugins`，原生默认 `/var/lib/qbot/plugins`，不要把它们再次放进 `/opt/qbot/current`。旧目录的自定义插件先校验 manifest 再迁出；拒绝符号链接和重复 ID 冲突。升级前单独复制整个插件目录可避免清理旧发布目录时丢失未登记插件。
5. 本地 Ollama 需管理员明确设置 `OLLAMA_ALLOWED_BASE_URLS`；旧配置不会自动获得私网豁免。需要跨供应商备用时，在主模型编辑中明确开启，并确认备用模型已授权、已启用。
6. 旧 GitHub 检查或推送重试任务若没有有效创建者，将拒绝执行，管理员应重新创建并授权；有效任务也会在每次执行时复核创建者的当前权限和仓库范围。默认备份、清理任务不受此授权迁移影响。历史 `owner_user_id=NULL` 仓库只能沿用旧全局语义，管理员应审计并重新指定归属。

## 恢复与中断

- Docker 恢复脚本先校验 gzip / 可用 SHA-256、在随机隔离数据库导入并核对必要业务表与已知 Alembic revision；`--verify-only` 不停止业务且不覆盖运行数据库。
- 正式恢复需确认 `RESTORE`，停止本 Compose 的 backend/worker 并创建当前数据库快照，再用单事务导入。失败时服务保持停止，先检查恢复前快照和日志，再人工决定恢复或启动。其它主机写入者必须由管理员另行停止。
- 原生 updater 的安装、迁移或启动检查失败可在维护闸门开放前恢复旧代码和升级前数据库；写入闸门已开放后，不自动覆盖数据库。
- 新版本接受新写入后，直接切回旧代码不受支持；需要停写、保存当前数据，再恢复升级前完整快照，或另行设计向后数据迁移。恢复旧快照会丢失快照后的新消息、配置和任务记录。
- QQ 外部发送结果不由数据库回滚撤回。inbox 标为 `uncertain` 时先核对平台投递；不要为了重试把它直接改为成功，也不要宣称 exactly-once。

## 验证范围

`backend/tests/test_upgrade_data.py` 从带账号、加密密钥、仓库规则、任务、自定义插件绑定和重复会话的 v1.5.3 schema 升到当前 head；SQLite 本地执行，PostgreSQL 通过显式 `TEST_POSTGRES_URL` 创建随机独立库执行。CI 的 Compose smoke 运行真实 PostgreSQL 备份、隔离演练、停机恢复和恢复后登录检查。每次发布的实际结果及 NOT RUN 场景应查看当次验收报告，不能把测试定义视为已经执行。
